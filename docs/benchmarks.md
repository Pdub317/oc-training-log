# Benchmark Catalog

**Status:** Track catalogs captured; initial explicit SP benchmark fixture implemented; catalog expansion pending  
**Last updated:** 2026-09-02

Benchmarks are repeatable movements or workouts whose comparable scored results are retained in Personal Records. Display names should preserve coaching language while implementation uses stable identifiers.

## Score-type conventions

- Weighted max: pounds; higher is better
- Variable-rep weighted max: completed reps and pounds; compare within the recorded rep count unless a future policy defines cross-rep ranking
- Jump height: inches; higher is better
- For time: duration; lower is better
- Max reps, calories, distance, or rounds: higher is better unless explicitly defined otherwise
- Equipment configuration, band color, chain weight, box/foam setup, and unsuccessful attempts are optional details or notes

## Catalog implementation rules and cleanup

- A programming prescription must carry an explicit, validated benchmark link before its result participates in PR evaluation. Similar movement names or rep language are not sufficient.
- Dumbbell weights are stored per hand and displayed with an `each` label. Combined load is derived only when needed.
- Weight results may use any positive decimal pound value and are preserved without application rounding.
- Variable-rep weighted PRs are independent by completed rep count.
- Hurdle-test entries remain notes-only until the gym defines the measurement and comparison rule.
- Canonical identifiers and aliases are still required for common spelling or coaching variations so imported programming maps consistently without changing the displayed coaching language.
